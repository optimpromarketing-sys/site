# Оптим Про — справочник по страницам приложений

Актуализировано 27 октября 2026 года. Готовые HTML-фрагменты находятся в `apps/`. Инструкция сохранения и публикации: [publication-guide.md](publication-guide.md). ID страниц и компонентов: [deployment-map.json](deployment-map.json).

## Какие файлы редактировать

В репозитории шесть приложений: `optimgpt.html`, `geotrekker.html`, `laborcost.html`, `passport.html`, `translator.html`, `telemost.html`. Общий каталог — `apps/apps-page.html`.

`gen2.js`, `gen_imgcache.py`, `op-crm.css`, `op-crm.js` и `img_cache.json` в репозитории отсутствуют. Старые инструкции по запуску генератора не применяются. Редактируйте готовые фрагменты; установка пакетов и сборка для этого не нужны. Самостоятельные страницы и общий каталог могут иметь разные структуры и корневые селекторы — сохраняйте структуру конкретного файла.

## Разметка и стили

- HTML-блок — фрагмент с уникальным корневым ID, без вложенных `html`, `head` и `body`.
- Размещайте стили и скрипты в самом фрагменте. Ограничивайте CSS корневым ID; `body` и общий `.op-crm` не изолируют компонент от соседних блоков.
- JS ищет элементы внутри своего корня. Общие обработчики и оверлеи добавляйте однократно.
- Ссылки на другие страницы задавайте по реальным маршрутам Битрикс24. Путь файла в GitHub не определяет адрес страницы.
- Изображения: публичные абсолютные HTTPS-адреса или встроенные `data:image/...`. Относительный путь разрешается относительно опубликованной страницы, а не репозитория. `base64` — вариант хранения, а не обязательное условие Битрикс24.

## Дизайн

Основные акценты: cyan `#2FC7F7`, blue `#2E7DF6`, violet `#7A5CFF`. Тёмный фон `#080c17`, основной текст `#E8EDF7`. Заголовки — Montserrat, основной текст — Open Sans с системными fallback.

Подключайте необходимые начертания шрифта и проверяйте их фактическую загрузку. Битрикс24 не ограничивает Montserrat начертанием 400. `-webkit-text-stroke` в существующих файлах — декоративная обводка; не используйте её как обязательную замену `font-weight`. Для градиентного текста обводка может перекрыть градиент: проверяйте результат в браузере.

Тёмная тема по умолчанию: `html:not([data-theme="light"])`. Светлая: `html[data-theme="light"]`. Общий ключ темы — `op-theme`. Если компонент читает `localStorage`, обрабатывайте недоступность хранилища, не прерывая инициализацию контента.

## Содержание приложения

Рекомендуемый порядок: ценность и аудитория → задачи клиента → возможности → скриншоты → установка → подтверждённый результат → FAQ → следующий шаг. Сохраняйте реальные URL приложения в маркетплейсе; название приложения не определяет URL автоматически.

Консультация: `https://b24.pro/#b28970`. Это якорь формы на главной странице `1604`. Перед переносом формы проверяйте цель и обновляйте все затронутые переходы.

Не переносите демонстрационные числа в публикацию. Факты о клиентах, сроках, пользователях и тарифах должны иметь источник. Для сайта используйте Tone of Voice из `docs/Tone of Voice.docx`: конкретные условия, активный залог, короткие абзацы; без выдуманных показателей.

## Каталог и взаимодействия

В каталоге шесть приложений. При добавлении или удалении приложения обновляйте карточки, индекс поиска, фильтры, начальный счётчик и упоминания количества на главной.

Проверяйте поиск, категории, очистку, пустой результат и повторную инициализацию. Карточки не должны дублироваться после фильтрации. Дубли в бесконечной декоративной ленте отличаются от дублей записей каталога.

Для scroll reveal оставляйте контент видимым без JS или добавляйте fallback. Hero не должен ждать IntersectionObserver. Проверяйте загрузку изображений, прежде чем скрывать слайды; не полагайтесь на `loading="lazy"` для первоначально невидимого слайда.

## Проверка и публикация

1. Прочитайте актуальный GitHub `main`, черновик и опубликованный HTML_CODE. Сохраните снимки вне репозитория.
2. Внесите изменение в исходник, проверьте JS, ссылки, мобильную ширину и взаимодействия.
3. Непосредственно перед записью повторите чтение черновика и остановитесь при чужом изменении.
4. Сохраните HTML_CODE по [publication-guide.md](publication-guide.md), прочитайте обратно и сравните исходники.
5. Опубликуйте только затронутую страницу. Проверьте публичный URL и опубликованный HTML_CODE, затем сохраните проверенный результат в GitHub.

Загрузка CRM-формы проверяется без отправки обращения. Отчёты от 7 октября описывают историческое состояние; актуальную проверку фиксируйте отдельной датой.
